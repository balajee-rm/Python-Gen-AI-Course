Step 1: Download and Test Qwen2.5-1.5B via Ollama
Open your command prompt or terminal and pull the base model into Ollama:

ollama run qwen2.5:1.5b

Step 2: Test the Base Model with Your Prompt
Copy and paste this exact prompt into the terminal where Ollama is running:

You are an academic advisor for CSE II Year. Analyze the target student against the class database and output the assessment in strict raw JSON without any markdown formatting or extra text.

Return JSON with these exact keys:
- "student_name"
- "overall_standing"
- "class_rank"
- "positives" (array)
- "negatives" (array)
- "suggestions_to_improve" (array)

Data:
Target Student: Alice Smith. Database: [{'student_name': 'Alice Smith', 'grades': [{'course_name': 'Data Structures', 'marks_obtained': 88, 'max_marks': 100}]}, {'student_name': 'Bob Jones', 'grades': [{'course_name': 'Data Structures', 'marks_obtained': 62, 'max_marks': 100}]}]

Step 3: Observe the Output
Notice how the base model responds. Check for common base-model issues:




output

```json
{

  "overall_standing": "Above Average",
  "class_rank": "3rd",

    "Potential need for improvement in other subjects"
  ],
  "suggestions_to_improve": [
    "Consider focusing on subjects that are underperforming"
  ]
}




Look closely at the output you just got from the base model. This perfectly highlights why fine-tuning is necessary:

Incorrect Calculation: There are only 2 students in the database (Alice with 88% and Bob with 62%). Yet the base model ranked Alice as "3rd"!

Markdown Wrapping: It wrapped the output inside ```json ... ``` backticks instead of returning clean, raw JSON ready for software parsing.

Generic Logic: It guessed generic negatives like "Potential need for improvement in other subjects" even though no other subjects were provided in the dataset.

Now, we move to Phase 2: Fine-Tuning with QLoRA to fix these exact errors!
